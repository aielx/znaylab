# ЗнайЛаб — лендинг детского образовательного центра

Одностраничный сайт на [Astro](https://astro.build). Статика: собирается в HTML/CSS/JS, деплоится на любой статический хостинг (Nginx, Netlify, Vercel, GitHub Pages, Yandex Cloud Object Storage).

> 📖 **Полное руководство по публикации на GitHub Pages с доменом и приёмом заявок через Google Sheets — в [`DEPLOYMENT.md`](./DEPLOYMENT.md).** Там пошагово: публикация, привязка домена `znaylab.ru` (DNS в Reg.ru), настройка формы заявки, решение проблем.

## Быстрый старт

```bash
npm install        # установить зависимости
npm run dev        # dev-сервер → http://localhost:4321
npm run build      # production-сборка в dist/
npm run preview    # локальный просмотр сборки
npm run images     # перегенерировать изображения из intellect/
```

## Структура

```

scripts/

src/
  content/                  # ВСЕ ТЕКСТЫ И НАСТРОЙКИ — править здесь:
    site.ts                 #   телефон, адрес, реквизиты, соцсети, id Метрики, эндпоинты

    reviews.ts              #   отзывы
    faq.ts                  #   вопросы-ответы
    photos.ts               #   (генерируется скриптом — не редактировать)
  components/               # блоки лендинга (Header, Hero, Directions, ... BackToTop)
  layouts/BaseLayout.astro  # <head>, SEO, Schema.org, PWA-мета, Метрика, noscript
  pages/                    # index + 404 + politika, oferta, oplata + thanks, errorpay
  styles/global.css         # дизайн-токены (цвета, шрифты), базовые стили
public/
  brand/                    # логотип (SVG + PNG 1x/2x/3x), favicon, PWA-иконки
  fonts/ images/ js/        # js/main.js — единый клиентский модуль

  robots.txt                # индексация + ссылка на sitemap

```

## Как менять контент

- **Тексты, цены, отзывы, FAQ** — файлы в `src/content/`. Цены — в `src/components/Schedule.astro`.
- **Телефон, адрес, реквизиты, ссылки** — `src/content/site.ts` (одно место на весь сайт, включая политику и оферту).
- **Фото**: положите новые JPG в `intellect/`, добавьте строку в массив `PHOTOS` в `scripts/optimize-images.mjs` (имя, категория, alt), запустите `npm run images`. В разметке фото вставляется компонентом `<Photo name="..." />`.
- **Логотип**: эмблема — точный вектор головы из `intellect/ЛОГО.eps` (извлечён в `scripts/head-paths.mjs`); собирается скриптом `scripts/generate-logo.mjs` → `node scripts/generate-logo.mjs`.
- **Варианты hero-заголовка** — комментарий в `src/components/Hero.astro`.

## Что нужно заполнить перед запуском (заглушки)

Сейчас в коде стоят **демо-данные** на основе «Интеллекта» — сайт выглядит законченно, но перед боевой публикацией замените их на реальные. Точки помечены комментарием `[ДЕМО]`:

1. **Реквизиты ИП** — `site.legal` в `src/content/site.ts`: `entity`, `inn`, `ogrnip`, `legalAddress`, `checkingAccount` (р/с), `bankName`, `bik`, `corrAccount` (к/с), `email`. Сейчас демо-значения в правильном формате; банк проверяет совпадение с ЕГРИП. Выводятся в футере, на странице `/rekvizity`, в оферте и политике.
2. **Отзывы** — `src/content/reviews.ts` (живые шаблоны; замените на реальные отзывы с Яндекс.Карт) + ссылка «Все отзывы на Яндекс.Картах» — `site.yandexMaps`.
3. **Домен** — `site` в `astro.config.mjs` и `Sitemap:` в `public/robots.txt` (по умолчанию znaylab.ru).
4. **MAX (мессенджер)** — `site.max` в `src/content/site.ts`.
5. **Часы работы** — `site.hours` / `site.ts`.

### Интеграции (`metricaId`, `paymentUrl`, `leadWebhook`)
Эти поля оставлены **пустыми** намеренно — подставлять демо-значения нельзя (чужой id Метрики сломает аналитику, нерабочий webhook — форму). Пока они пустые:
- Метрика не грузится → нет лишних запросов;
- кнопки «Оплатить занятия» скрыты;
- форма «Записаться» работает в демо-режиме: показывает успех и пишет данные заявки в консоль браузера.

## Интеграции (`src/content/site.ts`)

### Яндекс.Метрика
Заполните `metricaId` (число, id счётчика). Цели отправляются автоматически по `data-goal`:
`cta_pay`, `cta_signup`, `phone`, `max`, `telegram`, `lead_success`, `payment_redirect`, `reviews_yandex`.
Создайте эти цели (JavaScript-событие) в интерфейсе Метрики. Вебвизор включён.

### Заявки (форма «Записаться»)
Заполните `leadWebhook` — URL, куда уйдёт POST с JSON заявки. Варианты:
- **Telegram**: webhook-прослойка → `https://api.telegram.org/bot<TOKEN>/sendMessage`;
- **Google Sheets/CRM**: Apps Script или Albato/ApiX-Drive webhook;
- **E-mail**: любой form-backend (Formspree, свой скрипт).

Пока поле пустое — заявка пишется в консоль браузера (демо).

### Онлайн-оплата (ссылка на CRM/банк-эквайер)
Движок оплаты на сайте не встраивается — пользователь перенаправляется на платёжную страницу CRM/банка, затем возвращается на сайт. Настройка:
1. Впишите ссылку на платёжную страницу в `paymentUrl` в `src/content/site.ts` — тогда на сайте появятся кнопки «Оплатить занятия» (шапка, hero, блок цен, мобильная панель). Пока поле пустое — кнопки скрыты.
2. Впишите наименование банка-эквайера в `paymentProvider` (например `ПАО Сбербанк`) — оно подставится в тексты оферты и страницы «Оплата и возврат». Пустая строка — нейтральная формулировка «платёжный провайдер».
3. В настройках CRM/банка укажите return-URL'ы возврата на сайт:
   - успешная оплата → `https://<домен>/thanks`
   - ошибка оплаты → `https://<домен>/errorpay`

Return-страницы уже существуют и исключены из индексации (`robots.txt`), страница `/oplata` (способы оплаты и возврата) — индексируется.

## ✅ Compliance для интернет-эквайринга

Сайт подготовлен под типовой чек-лист Сбербанка / Т-Банка / ВТБ для подключения интернет-эквайринга (redirect-схема). Что уже реализовано:

| Требование банка | Где на сайте |
|---|---|
| Полные реквизиты ИП (ИНН, ОГРНИП, р/с, банк, БИК, к/с, юр. адрес) | Страница `/rekvizity` + футер (кратко) + оферта + политика |
| Публичная оферта (предмет, оплата, 3D-Secure, порядок услуг, возврат по ст. 32 ЗоЗПП, претензии, реквизиты) | `/oferta` |
| Политика конфиденциальности (152-ФЗ: цели, передача, отсутствие трансграничной передачи, сроки) | `/politika` |
| Согласие на обработку ПД + ссылка на политику и оферту | Чекбокс в форме заявки |
| Способы оплаты (карты МИР/Visa/MasterCard, СБП) + логотипы + 3D-Secure | `/oplata` |
| Условия и порядок возврата | `/oplata` + оферта §4 |
| Контакты (телефон, e-mail, адрес, часы работы) | Блок контактов + футер |
| Cookie-уведомление | Баннер + ссылка на политику |
| Страницы успеха/ошибки оплаты | `/thanks` (с № платежа из URL), `/errorpay` |

**Перед подачей заявки в банк** замените демо-значения (помечены `[ДЕМО]`) на реальные:
- `site.legal` — реквизиты ИП (банк сверит с ЕГРИП);
- `site.paymentProvider` — наименование банка-эквайера (после одобрения);
- `site.paymentUrl` — ссылка на платёжную страницу CRM.

**54-ФЗ (онлайн-кассы):** образовательные организации с лицензией при оплате только через сайт освобождены от ККТ (п. 13 ст. 2 54-ФЗ). ИП/ООО без лицензии обязаны применять онлайн-кассу — её обычно предлагает сам банк при подключении эквайринга. На сайте формулировки оферты (§2.4) покрывают оба случая.

## Деплой на GitHub Pages

Сайт автоматически собирается и публикуется через GitHub Actions (`.github/workflows/deploy.yml`) при пуше в `main`.

### Первичная настройка (один раз)
1. Запушьте репозиторий на GitHub.
2. В репозитории: **Settings → Pages**:
   - **Source** = `GitHub Actions` (именно так, а не ветка).
3. Подключите кастомный домен `znaylab.ru` (файл `public/CNAME` уже добавлен):
   - **Settings → Pages → Custom domain** → впишите `znaylab.ru` → **Save**;
   - у регистратора домена добавьте DNS-записи (см. подсказку GitHub в том же разделе): `A`-записи на IP GitHub Pages и/или `CNAME www → aiex.github.io`;
   - после проверки включите **Enforce HTTPS**.
4. Сделайте любой коммит в `main` — запустится workflow, через ~1–2 мин сайт будет доступен по `https://znaylab.ru`.

### Особенности сборки
- `astro.config.mjs` читает `SITE_URL` / `SITE_BASE` из окружения (дефолт `https://znaylab.ru` / `/`). Для деплоя на `github.io/<repo>` задайте их в workflow, чтобы canonical/OG/sitemap строились правильно.
- Кастомная `404.html`, `manifest.webmanifest`, `sitemap-index.xml`, `CNAME`, `robots.txt`, PWA-иконки собираются в `dist/` автоматически.

### Деплой на другой статический хостинг (Nginx, Netlify, Vercel, Yandex Object Storage)
`npm run build` → содержимое `dist/` — на хостинг. Для Nginx достаточно отдать статику. Страницы `/oplata/*` исключены из индексации через `robots.txt`.
